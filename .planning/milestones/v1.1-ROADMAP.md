# Milestone v1.1: World & Growth Overhaul

**Status:** ✅ SHIPPED 2026-03-07
**Phases:** 06-11
**Total Plans:** 24

## Overview

v1.1 turned the original short-session combat baseline into a deterministic world-and-growth loop. The shipped scope now covers scalable sector traversal, tactical building usage, breakable loot and equipment, XP progression, deterministic level-up choices, and milestone-level replay/restart regression coverage.

## Phases

### Phase 06: World Sectors & Spawn Determinism

**Goal:** Deliver scalable world sectors with deterministic traversal and spawn rules.
**Plans:** 4 plans

Shipped outcomes:
- Hub-plus-ring sector topology became the canonical source of truth for traversal, collision, and spawn ordering.
- Runtime now exports stable `world`, `spawnState`, and readability fields through `render_game_to_text()`.
- Browser and contract tests prove three-sector traversal, sector-boundary stability, deterministic spawn routing, and topology-derived readability.

### Phase 07: Building Tactical Layer

**Goal:** Integrate tactical building archetypes with stable collision and steering behavior.
**Plans:** 4 plans

Shipped outcomes:
- Added deterministic `blocker`, `funnel`, and `soft-cover` building archetypes as sector-authored world contracts.
- Player collision and enemy steering now reuse the same building semantics without regressing map traversal.
- Runtime exports stable `world.buildings` and `world.tactics`, and browser routes prove line-break, kite pivot, and retreat-pocket usage.

### Phase 08: Breakables, Loot, and Equipment

**Goal:** Ship deterministic breakable -> loot -> equip combat loop.
**Plans:** 4 plans

Shipped outcomes:
- Added authored non-blocking breakables that can be damaged and destroyed during normal combat flow.
- Added isolated loot RNG, weighted equipment drops, and deterministic ground-drop state.
- Added equipment slots, compare mode, stat deltas, and effective combat stats derived from base constants plus equipment deltas.

### Phase 09: XP & Level Progression Core

**Goal:** Establish configurable XP/level progression and in-run reset correctness.
**Plans:** 4 plans

Shipped outcomes:
- XP is now kill-driven and fully separate from score.
- Explicit progression thresholds and pending level-up queueing provide deterministic upgrade events without pausing combat.
- HUD, banner cues, and `progressionState` snapshot fields expose progression state for both gameplay and automation.

### Phase 10: Skill/Talent Choice Engine

**Goal:** Implement deterministic level-up choices with skill/talent constraints.
**Plans:** 4 plans

Shipped outcomes:
- Added authored upgrade catalog constraints and deterministic offer generation.
- Added `levelup_choice` modal flow with exactly three options, one-shot reroll, and explicit queue consumption semantics.
- Applied upgrades now flow through effective-value helpers and ship with stable `levelUpState` / `upgradeState` snapshot evidence.

### Phase 11: Automation & Determinism Hardening

**Goal:** Harden v1.1 observability and end-to-end deterministic regression coverage.
**Plans:** 4 plans

Shipped outcomes:
- Froze the milestone snapshot contract under schema `1.4.0` with top-level RNG evidence.
- Added dual-session replay parity, dedicated restart parity, and helper-backed browser routes for loot and level-up flows.
- Added stable `npm run test:e2e:v11` and `npm run test:regression:v11` commands as the milestone regression surface.

## Milestone Summary

**Key Decisions:**
- Sector topology and readability remain one shared source of truth for runtime and deterministic assertions.
- Building and breakable semantics stay isolated to avoid collision and steering rule bleed.
- Loot, progression, and level-up randomness each use dedicated deterministic state instead of reusing older random flows.
- Effective combat stats are derived additively from base constants plus equipment and upgrade deltas.
- `render_game_to_text()` plus named regression scripts are the canonical verification surface; screenshots are debugging aids only.

**Issues Resolved:**
- Removed map-scale limits caused by single-arena assumptions.
- Closed deterministic gaps between traversal, spawn, loot, progression, and level-up systems.
- Added browser-level parity checks for replay and restart so the full loop is regression-safe.

**Issues Deferred:**
- Meta-layer features such as local best-score history and daily seeded runs.
- Persistent progression and long-term inventory/stash systems.
- Cleanup of historical phase directories, left for `$gsd-cleanup` by explicit choice.

**Technical Debt Incurred:**
- Headless browser runs still emit known WebGL fallback and offline-resource noise, though v1.1 verification no longer relies on screenshots as truth.
- Workspace still contains legacy planning artifacts and local scratch files that must stay excluded from future archival and release commits.
